解密 GitHub Actions：deploy.yml 到底在做什麼？

這份課程會帶您了解我們剛剛為 IG 貼文產生器加入的自動部署腳本 deploy.yml 的背後原理。

什麼是 GitHub Actions？

想像 GitHub Actions 是您專屬的「雲端管家」。當您對專案做出特定動作（例如上傳程式碼）時，管家會依照您事先寫好的「工作清單」自動幫您跑指令。這份清單就是我們的 deploy.yml。

逐段解析 deploy.yml

讓我們來看看腳本中最重要的幾個部分：

1. 觸發條件 (Triggers)

on:
  push:
    branches: ["master"]
  workflow_dispatch:

這告訴管家什麼時候該上班。push: branches: ["master"] 代表「只要有人把程式碼推送到 master 分支，就立刻開始執行」。workflow_dispatch 則是允許您隨時在 GitHub 網頁上手動點擊按鈕執行。

2. 權限設定 (Permissions)

permissions:
  contents: read
  pages: write
  id-token: write

這是給管家的「通行證」。我們允許它讀取我們的程式碼 (contents: read)，並且允許它有權限把產生的網頁發布到 GitHub Pages 上 (pages: write)。

3. 工作內容 (Jobs & Steps)

接下來是具體要管家執行的每一個步驟 (Steps)，就像是廚師看食譜做菜一樣：

steps:
  # 1. 把最新的程式碼抓下來
  - name: Checkout
    uses: actions/checkout@v4
    
  # 2. 準備 Node.js 環境 (就像在您的電腦上安裝 Node)
  - name: Set up Node
    uses: actions/setup-node@v4
    with:
      node-version: 20
      
  # 3. 安裝我們需要的工具套件
  - name: Install dependencies
    run: npm ci
    
  # 4. 把 React 程式碼打包成瀏覽器看得懂的 HTML/CSS/JS (放到 dist 資料夾)
  - name: Build
    run: npm run build
    
  # 5 & 6. 把打包好的 dist 資料夾上傳到 GitHub 伺服器並發布
  - name: Upload artifact
    uses: actions/upload-pages-artifact@v3
    with:
      path: './dist'
      
  - name: Deploy to GitHub Pages
    id: deployment
    uses: actions/deploy-pages@v4

總結

簡單來說，deploy.yml 就是在雲端租一台 Linux 電腦，把您的程式碼抓下來，執行 npm run build，最後把打包出來的 dist 網頁丟給 GitHub Pages。這讓您完全不用在自己電腦上手動打包！
